# 判据的注释是契约，实现要对得上

## 血案

一条规则的文件头写着四档处理：

```
空体 / 只有注释            → 报
只有 console.* / logger.*  → 报
有 return 兜底值但无上报    → 不报
有 throw / 上报 / 事务回滚  → 不报
```

实现却只看 `body.split('\n')[0]` 是不是日志调用：

```ts
const onlyLog = /^(console|logger)\./.test(body.split('\n')[0] ?? '')
if (onlyLog && isWrite) push(hit)
```

于是 `logger.warn({...}); return { ok: false }` —— 第二行就是文件头承诺放过的
「有兜底值的降级」—— 照样报红。目标仓 36 条里抽 5 条，4 条是这一形态：
解析失败返回 `ok:false`、通知失败让主流程继续、补偿槽清理失败但主操作已提交。

同一天还撞到第二例：另一条规则的注释写「捕获 P2002 不报」，词表里也只有字面量
`P2002`。目标仓把唯一冲突封装成 `isUniqueViolation(e)` —— 封装名不在词表，
于是「已经写得很规范」的两处被报成「无冲突处理」。

**越规范的项目误报越多**：它把细节封装掉了，而封装名不在你的词表里。

## 判据纪律

1. 写规则时，先把注释里的「不报」条件逐条抄成一个 fixture。抄不出来的那条，
   说明它只是愿望，不是实现 —— 现在就不要写进注释。
2. 判断「catch 里还有什么」必须真的**删掉调用**再看待剩余，不能看第一行：
   有 `return` / 赋值 / 状态写 ⇒ 已声明降级。
3. 日志级别是语义：`logger.error` = 自称事故，`logger.warn` = 已知可容忍。
   「只打 error 日志且没有收口动作」是自相矛盾，该报；`warn` 是设计选择，不该报。
4. 词表要收**项目自己的封装名**：`isUniqueViolation` / `23505` / `UniqueConstraintError` /
   `onConflict`。只收标准错误码等于强迫所有项目不封装。
5. 写路径要分「观测面」和「业务表」：信号/审计/留证/幂等锚写失败时**没有更上一层的
   收口手段**（再抛只会带崩主流程），把它们算成吞异常，等于要求「记日志失败必须让主流程也失败」。

## 反证

```
logger.error(...) 单独              → 报
logger.warn(...) 单独               → 不报（声明可容忍）
logger.error(...) + return 兜底      → 不报
try 只写 adminSignal，catch 打日志   → 不报（观测面，无上层收口）
try 写 record.update，catch 打日志    → 报
catch 里 isUniqueViolation(e)       → 不报
catch 里 logger.warn 但没判错误类型  → 报
```

## 怎么问

- 这条判据声称放过哪几种写法？把它们写成字符串样本，跑一遍，真的绿吗？
- 目标项目把标准错误码封装了吗？封装后的名字在词表里吗？
- 这个 catch 里失败的写，是业务数据还是观测数据？丢了以后谁来兜？
