# 声明式机制写对了不等于生效了——生效条件不在那个写法里

## 血案

三个同构的事故，都在同一个仓里，表面上互不相关：

**① 样式在组件里静默失效。** 排版类集中写在全局样式里，页面一直正常。
把这块结构抽成自定义组件、类名照抄——**看起来完全没变，实际全丢了**。
自定义组件默认样式隔离，全局样式不作用于组件内部。
类名写得对、样式定义也在、工具不告警；真机上只是「字号小了一号、颜色淡了」，
靠人眼在两台设备上比对才可能发现。

**② 页面漏登记。** 新增页面目录，四个文件齐了，开发者工具里手点能打开，
编译、lint、类型检查全绿。漏了往注册表加一行。
只有真机通过跳转 API 进入时必然失败（`page "…" is not found`）。
分包更隐蔽：注册串要拼上分包 root，代码里的绝对路径少一个前缀就永远匹配不上，
而两处各自都是「对的」。

**③ 返回在栈底静默失败。** 「提交成功 → 提示 → 稍后自动返回」。
正常路径（从列表点进来）没问题。分享卡片直达、扫码直达、`reLaunch` 之后，
页面栈深度为 1，返回调用**不抛错、不中断**，只是失败。
用户看到「提示说成功了，然后停在一个已提交的表单页上，什么也没发生」。

共同点：**声明式机制的生效条件，不在那行写法里。**
样式写了，生效与否取决于隔离配置；页面建了，能否跳取决于注册表；
返回写了，能否退取决于进入方式。三处都没有「写错」的代码可供 review 抓到。

## 判据纪律

1. **每个声明式写法都要问「它的生效条件是什么」。**
   隔离配置、注册表、页面栈深度、权限声明、feature flag——条件不写在使用点，
   写在使用点的那一行就永远看不出问题。
2. **「工具里能跑通」不是证据。** 开发者工具按文件路径找页面、按宽松规则渲染样式，
   它比真机宽松。判据要以**真机的解析规则**为准（注册表 + 隔离默认值 + 运行时栈深）。
3. **只在能证死的交叉点上说话。** 「类没定义」可能是 JS 查询锚点（刻意的），
   不报；「类只在全局定义」证明写的人**以为**它有样式，报。
   这个区分决定了判据能不能长期留在 CI 里。
4. **注册表类判据必须找到注册表本身。** 页面路径的基准目录要和注册表来自同一个事实
   （注册表就写在那个文件里），不要另行「按配置声明一个根」——
   两处各算一次前缀，错的那次会产生一整片假红。
5. **静默失败比报错贵。** 这三类都不抛异常，所以它们不会被日志、监控、重试发现。
   判据是唯一会说话的那个角色。

## 反证

```
组件用了 app.wxss 的类，自己没定义        → 必须报（隔离默认生效）
组件声明 apply-shared / addGlobalClass    → 不该报（条件确实成立）
类由 @import 或 externalClasses 提供      → 不该报
跳转目标不在 app.json                     → 必须报
跳转目标由变量拼装                        → 不该报（不猜运行时值）
返回带 fail 兜底 / 先判栈深                → 不该报
```

## 怎么问

- 这行写法要生效，前提是什么？前提写在哪个文件里？谁保证它们一致？
- 如果前提不成立，会报错、会静默、还是会「看起来对但效果不对」？
- 这个功能在**非正常入口**（分享直达、扫码、深链、刷新后重进）还成立吗？

## 另外两个形态：类型写在配置里，定义写在别处

- **`MP006` 跳转 API 与目标页类型不匹配。** `wx.navigateTo` 的写法完全没问题，
  但目标页在 `app.json` 的 `tabBar.list` 里——真机 `can not navigateTo a tabbar page`，
  用户点了没反应。反向同型：`switchTab` 指向非 tab 页。
  API 选得对不对，取决于「目标是什么类型」，而那个类型写在**你没打开的那份配置**里。
- **`MP008` 类名写了，但作用域内谁都没定义它。** 少一个字母（`prodcut-card`）、
  或者样式留在了**页面**的 wxss 里而模板抽成了组件——页面上什么都不发生，控制台也不说话。
  它比 MP002 更隐蔽：MP002 至少「全局定义了、组件拿不到」，这里连定义都没有，
  你打开全局样式会以为「应该生效啊」，因为名字长得太像。
  例外要认：类名若被 JS 当查询锚点（`createSelectorQuery().select('.measure-box')`），
  没有样式是**设计如此**，不是缺陷。
