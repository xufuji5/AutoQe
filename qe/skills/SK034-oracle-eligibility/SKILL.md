# 判据的资格

## 真实形态

一条判据红了，人会去改代码。如果那条判据的真值本身是猜的，人就是在**为一把凭空发明的尺子改代码**。
这比不扫更贵：它消耗信任，而且会把人带偏。

所以立项时先答两个问题：

1. **你的 oracle 是谁**——真值从哪来？必须是「换个人也能复算」的事实（schema、AST、文件存在性、
   字符串语义）。答「经验」「惯例」「一般来说」的，一律不算。
2. **谁守这个 oracle**——载体自己有没有守卫？文档库没人同步，就没有资格评价代码；
   登记表没人对账，就没有资格说「已登记」。

## 机器怎么执行

`qe/registry/rule-oracles.ts` 是单源登记，`scripts/verify-rule-oracles.ts` 是执行者：

| 纪律 | 后果 |
|---|---|
| 规则没登记 oracle | `toGuard` 在**导入期**抛错 → 规则连跑都跑不起来 |
| oracle 是 `human` 却标 `error` | 导入期抛错：机器只能出候选 |
| `human` 没写 `why` / `promoteBy` | CI 红：候选池必须到期升级，不许变成永久噪声 |
| `guardedBy` 指向不存在或未 enforced 的不变量 | CI 红：载体自己没人守，没资格评价别人 |
| `human` 候选池超过 3 条 | CI 红：候选池会变成第二个人工待办池 |

校验器自己也有 11 条合成坏表先红后绿——**一个只会跑真实表的校验器，红了也说不清是表坏了还是它坏了。**
