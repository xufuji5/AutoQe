# 开发期脚手架残留

AI 为了让流程先跑通，会在三个位置留下脚手架。它们的共同点是**不报错、类型正确、演示时一切正常**：

| 形态 | 写法 | 为什么危险 |
|---|---|---|
| 假闸门 | `verifyX(a, b) { return { ok: true } }` | 调用方以为每次都被校验，实际每次都被放行；闸门只存在于代码里 |
| 真出网脚本 | 冒烟脚本直接 `fetch('https://…')`，没有先引入强制 mock 环境 | 跑一次就产生真实出账/真实消息；崩溃常发生在后续断言之前，脚本仍打印「清理完成」 |
| 兜底假数据 | `if (!isProd) return [{…}, {…}]` 或 `catch { return [{…}] }` | 接口挂了、鉴权配错、环境变量漏配时，界面照常「有数据」，问题被盖住 |

三类都不是「写错」，而是**写少了一段**：少一次读入参、少一行 mock 引入、少一次诚实降级。

## 判据

| 判据 | 能证死的事实 | 档位 |
|---|---|---|
| `aq16`（INV-RES-04） | 函数名以校验动词开头、有形参、首句无条件返回通过，且函数体从未出现任何形参名 | machine → error |
| `aq17`（INV-RES-03） | 自测脚本里可证的出网地址（绝对外部主机 / 去变量后仍是公网域名的模板）或支付 SDK import，且没有引入强制 mock 环境模块 | machine → error |
| `aq18`（INV-RES-05） | dev 门控分支或 catch 里 `return` 字面量数组（≥2 项）/ 单条 ≥2 字段记录 / 含数据字段的对象，且 catch 无重抛 | machine + human 候选 → warn |

三条都只认**可复算的形态**：aq16 不评价校验强度，aq17 不证明运行期一定出网，aq18 不判断数据意图。
清单问的是它们背后那句话：**「这份脚手架如果留着，系统在哪一步开始说假话？」**

## 自省

- 这个函数读了它的入参吗？还是它只在签名里收了参数？
- 这个脚本在 CI 里跑一次，会不会产生一条真实消息、一笔真实出账、一张真实图片？
- 这段兜底数据在接口 500 时会不会被当成真数据展示？返回空数组和返回三条示例，哪个更诚实？
- 我删掉这段脚手架之后，哪条断言会红？如果一条都不会红，说明它本来就没有被验证过。
