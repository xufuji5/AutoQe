# 扫描器不认识正则字面量，于是把文档当代码

## 血案

试点 C 首轮 AQ001（裸 `req.json()`）报了 8 处，**7 处在注释里**：

```ts
 *   ① `const body = await req.json()` → `body.orderId`
 *   ② `const dto = schema.parse(await req.json())` → `dto.orderItemId`
```

而 AQ001 明确调用了 `maskStringBodies(stripComments(src))`。工具没错，**扫描器错了**。

根因只有一行代码：

```ts
const m = s.match(/^https?:\/\/([^/`'"?${]+)/)
```

字符类里有反引号、单引号、双引号。手写扫描器只认「代码/行注释/块注释/字符串」四态，
走到这个正则时把反引号当成模板串开场 —— 此后**整个文件都被当成字符串内容原样透传**，
注释不再被剥，于是文档文字进了分析面。

## 为什么这类失效特别贵

它不是漏报，是**反向失效**：越认真写文档（示例、反例、错误写法清单），误报越多。
于是最规范的文件被报得最红，人得出的结论是「这工具对好代码过敏」，然后整条规则下线。

同时它有第二个方向：状态错位后剩余文件按字符串透传，**真洞也会一起消失**（假绿）。
同一处 bug 既能造假红，也能造假绿 —— 所以它必须由自证例钉住，不能靠跑一遍看读数。

## 判据纪律

1. 手写扫描器必须认全定界符：`//`、`/* */`、`'`、`"`、`` ` ``、**正则字面量**。
   正则的开场判定看「前一个有意义字符」`( , = : [ ! & | ? { } ; + - * % ~ ^ < >`
   与关键字（`return` / `case` / `typeof` / `match(` …）；判不出来就**退回原语义**，
   宁可漏认也不能假装认出了正则。
2. 正则不跨行：同一行内没有闭合的 `/` 一律不当正则（除号）。
3. 修复必须同时进 `maskStringBodies` —— 它也在同一份源码上走状态机，
   正则里的引号会把后续代码整段抹成空白（从假红变成假绿，更糟）。

## 反证必须留三个方向

```
正则字符类里带引号/反引号  → 其后的块注释仍必须被剥（本次事故的最小复现）
除号 total / 2             → 不许被当正则（否则吞掉后半行）
真正的裸 await req.json()  → 必须照旧报
```

只留最后一条，等于允许扫描器在自己舒服的样本上永远正确。
