# 判据扫到了「描述缺陷的文字」

## 血案

AQ001（裸 `req.json()`）在 试点 B 首轮报了 5 处，**5/5 全是误报**：

```ts
// scripts/invariants/registry.ts —— 不变量登记表的说明文字
statement: "输入在边界声明式校验；禁 as 断言、禁裸 req.json() 透传、禁请求方自报身份。"

// scripts/verify-boundary-validation.ts —— 判据自己的报错模板
check(`B4 裸 req.json() 站点 ${rawCount} ≤ 上限 ${CEILING}（不许新增）`, ...)
```

一个是「写着禁止这个洞的规范文本」，一个是「统计这个洞的守卫代码」。
它们描述的对象是洞，但它们本身不是洞。判据把「描述」当成了「发生」。

## 为什么这类误报特别贵

它命中的文件通常**正是守卫自己的文件**。于是：

1. 读数看起来完全正常（有文件、有行号、有代码片段）；
2. 人一看是自己写的守卫，判定「这工具不准」，然后关掉整条规则；
3. 真洞在新代码里继续存在。

## 判据纪律：分析前先屏蔽字符串内容

任何「找某个调用/某个字面量」的静态判据，第一步必须是
`maskStringBodies(stripComments(src))`，不是 `stripComments(src)`。

`stripComments` 只处理注释；字符串里的 `req.json()` 仍然完整留在代码面上。
`maskStringBodies` 把字符串**内容**抹成等长空白（保留引号与换行），
于是行号不变、`=>}` 结构不变，只有内容没了。

## 反证必须留两个方向

```
字符串里描述出的 req.json()      → 不该报
模板串里的报错文案带 req.json()  → 不该报
真正的 await request.json()      → 必须报
```

只留前者会得到一个「永远不报」的规则（恒绿），那比误报更糟。

## 怎么问

- 这个命中点所在的那一行，是在**执行**，还是在**引用/说明**？
- 判据是不是只剥了注释、没屏蔽字符串？
- 我把字符串内容抹掉之后，还剩几条？（该剩的就是真洞数）
