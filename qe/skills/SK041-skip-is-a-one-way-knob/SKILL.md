# 跳过是单向旋钮

## 血案

一次全量复扫，`QE_RESULT ... skipped=6`。没人追问那 6 个是什么。
后来给每条跳过加上分类打印，才看到真相：

```
inv06=CONTRACTS_MISSING      inv07=CONTRACTS_MISSING
inv22=NO_ZUSTAND_STORE       spec-abs=SPEC_DOCS_UNSET
leak-project-info=SELF_ONLY_GUARD   aq02=STATE_VALUES_UNSET
```

六条判据，各自因为一个前提不成立而**整条空转**。而这六条在棘轮基线里
**一条键都没有** —— 于是「六条判据不看了」这件事，在 `regressions=0` 的读数上
完全隐形。

## 为什么它比「漏报」更危险

漏报至少还留下一个错的绿灯。跳过留下的是**更好看的绿灯**：

| 动作 | findings | 读数 | 棘轮 |
|---|---|---|---|
| 找到 5 条缺陷 | 5 | 黄/红 | 记 5 条键 |
| 改成「本轮不适用」 | 0 | **绿** | 键消失（读成改善） |

动机完全单向：任何一条难判的判据，只要把射程缩到「容易判的那部分」，
读数只会更好看，而且**没有任何一处会变红**。这不是有人故意放水，
是压力自然流向的方向。

## 判据纪律

1. **跳过必须两段：`(code, reason)`。** `code` 稳定、进棘轮键；`reason` 人读、
   不进任何键（自由文本做键会把「改了措辞」读成「换了缺陷」）。
   单参数构造一律不提供——让编译器当这条判据，比运行时再判一次「你忘了分类」省一层。
2. **同一前提关掉的判据必须共享同一个 code。** 8 个小程序规则都因为「这不是小程序工程」
   空转，裸字符串让它们在棘轮里各记一条 `AQ_NOT_CLASSIFIED`，读起来像八件不同的事；
   事实是**一件事**关掉了八条判据。共享前置（`requireMiniProgram`）要返回带 code 的对象，
   否则「同一前提空转了哪些判据」这个最有用的问题在读数上问不出来。
3. **首次登记 ≠ 射程缩小。** `baseline=0` 的键是「基线里本来没有这一类」
   （新判据上线、或机制迁移），和「原来那类变多了」要用不同文案，
   否则人会去修一件根本没发生的事。
4. **别用「skip 判红」当解法。** 很多跳过是正当的（外部仓没 Prisma schema 就是判不了）。
   要治的是**不可比较**，不是「不许跳过」。
5. **反证方式**：改掉某一类跳过的 code，读数必须变 `regressed`。实测：
   `iso01:SKIP:NO_VENDORED_ENGINE → NO_VENDORED_ENGINE_SILENTLY_WIDENED`
   ⇒ `regressions=1 improvements=1 status=regressed`，还原后 `ok`。

## 顺带的收获

`return []` 是跳过的**伪装形态**：判据不抛 `NotApplicable`，直接返回空 findings，
在读数上和「检查了，没问题」一模一样。规则型守卫的公共出口必须拦住它
（`rule-guard` 的「射程内 0 个文件 → 抛 NotApplicable」就是这条），
否则第 1 条纪律可以被绕过而不触发任何报错。
