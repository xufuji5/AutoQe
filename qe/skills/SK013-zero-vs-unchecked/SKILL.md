# 零命中 ≠ 零缺陷

## 血案（就在接入第二个项目的第一天）

AQ002 在 试点 B 报 268 处，在 试点 A 报 **0 处**。同一份代码、同一条规则，
两个数字看起来都是合法的读数。真相是：试点 A 没有 prisma `enum`、也没配
`stateValues`，规则进到 `analyzeSource` 里发现「没有状态值可判」，
`return []` —— **它根本没查**。

报告里那行写的是「0 处命中」。读的人会理解成「本仓没有状态旁路」。
该项目的一条铁律「读数必须能区分『没做』和『没有』」在这里被违反。

## 三个必须同时存在的机制

| 机制 | 缺了会怎样 |
|---|---|
| 规则声明 `precheck` 退出原因 | 规则自己知道没生效，但没人看得见 |
| 运行时把跳过打印在报告头条 | 读者把 0 当结论 |
| 跳过的规则**不建账** | 补上配置那天，几百处存量被算成「新增」，一次假红潮 |

第三条最反直觉：建一个「0 处存量」的账本，等于宣布「这条规则当前干净」。
账本一旦存在，棘轮就把后续所有命中判成新增。

## 怎么问

- 这条规则的 0，有没有可能来自「前置条件不满足」？
- 规则需要的输入（schema / 配置 / 声明表）缺失时，它是报错、跳过，还是返回空？
- 补上输入之后，那些历史命中会被算成存量还是新增？

## 修复形态

```ts
precheck(ctx) {
  if (stateValuesOf(ctx).size === 0) return '找不到状态值来源：无 prisma enum 且未配 stateValues'
  return null
}
```

配套运行时：跳过 → 报告头条打印 → 账本不写。
