# 自证例存在，不等于自证例被跑

## 血案

一个源码处理模块里有 22 条自证例，文件头写着：

> 自证例必须被 `autoqe selftest` 跑到 —— 工具自己错了，所有用它的判据一起错，而且错得安静。

实测：`grep CODE_ONLY_SELFTEST` 除了定义处**零引用**。`selftest` 只跑守卫的 fixture，
这 22 条一次也没执行过。读数 `cases=80 passed=80 green` 完全真实 —— 只是不含它们。

补上挂载后立刻变成 `cases=102`，并且**当场红了一条**：修复扫描器后新暴露的
`≥ 0` 恒真断言（此前被状态错位挡住，属于假绿）。

## 为什么这类缺陷不会自己暴露

它是「登记制退化成存在性检查」的又一次变体：

- 文件存在、函数有名字、注释写着"必须跑" —— 三样都在，判定成立；
- 唯一不在的是**调用边**；
- 而调用边缺失没有任何症状：不报错、不告警、覆盖率看起来还很高。

同一个根的三种形态，本库已记过两种：登记表里的 `at` 串还在但事实已不在（§18）、
守卫登记了但从没入闸（INV）。自证例是第三种：**判据自己的判据没人跑**。

## 判据纪律

1. 自证例必须有**挂载点**，且挂载点要能在读数里看见数量变化：
   `cases=N` 里 N 必须包含它们。只打印「22 条全过」而不并进总数，等于没并。
2. 新增自证模块时，先改总数再来写样本 —— 先写样本再想起来挂，通常就忘了。
3. 允许的形态只有两种：被 `selftest` 聚合，或被某个守卫的 fixture 直接引用。
   「放在那儿等人跑」不算形态，那是注释不是机制。
4. 判据写成 `grep 定义 + grep 引用` 双查：只有定义处 = 孤儿自证例。

## 反证

```
删掉挂载行     → cases 总数的读数必须变化（证明它真的并进去了）
把某条样本改红 → selftest 必须整体 red（证明不是「并了但没算」）
```

两条都过，才算「被跑」；只过第一条，只是「被打印」。

## 怎么问

- 这条自证例，谁调它？说出那行调用，而不是那个文件名。
- 它红了，会让哪条命令的退出码变成 1？
- 我这次的 `cases` 比上一轮多了几条？对得上我新写的条数吗？
