# 状态裸字面量旁路
## 长什么样

```ts
if (order.status === 'PAID') { ship() }        // ← 状态语义的第二份副本
```

状态机本应只在家里（`state-machine.ts`）被回答，但每个调用点都能自己再判一次。

## 为什么贵

加一个状态、改一次转移规则，你得 grep 全仓。**漏掉的那一处不会红**，
它只是行为不同 —— 几个月后表现为「同一状态在两个页面显示不同」。

## 怎么判

1. 从 Prisma schema 的 `enum` 自动抽状态值（**不猜**；没有 enum 就用配置的 `stateValues`，
   两者都没有则规则静默跳过 —— 宁可少报也不瞎报）；
2. 找 `status === '<值>'` / `!==`；
3. 排除「状态语义的家」（`ownerModules`）—— 那里的工作就是裸写状态。

## 为什么用 schema 自动提取而不是人工登记

登记制会退化：新增状态时没人会回来更新表，新状态永远不被守。
schema 是单源，加字段的人必须改它，判据自动跟上。

## 修复形态

谓词化：`if (isPaid(order))`。谓词只有一份，改规则时只改它。
