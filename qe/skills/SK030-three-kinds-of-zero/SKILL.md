# 零的三义

## 真实形态

某条钩子文案在页面上**从未出现过**。查表面事实：依赖的排期表 0 行。
结论写成「机制在、数据零，等真实数据长出来再验」。

实际情况是：**服务端从来没有下发过这个字段**。表填满了也不会变一个字。
修法完全不同——一个是等，一个是接线。

## 三种零

| 零 | 事实形态 | 修法 | 判据形态 |
|---|---|---|---|
| **未接线** | 写它的代码不存在（grep 不到写点/下发点） | 补布线 | 可以判：写点/读点是否存在（INV-CORE-01/02/06） |
| **未产生** | 代码在、数据没长出来（表 0 行） | 等或造夹具 | 只能读数，不能判红（数据没长出来不是缺陷） |
| **未触发** | 代码在、数据在、条件没到（时间窗/灰度/权限） | 等条件 或 造条件 | 造夹具验证，然后留待办 |

三者在**聚合读数**上完全一致（都是 0）。区分它们必须多走一步：**顺着链路找到写点**。

## 为什么对账永远发现不了

这类缺陷不产生错账，它产生**没发生的主流程**：没有请求、没有补偿、没有差错纪录。
账本永远干净，只是某条链路从未跑过。常规的「数字对不对」型检查对此免疫。

## 自省

- 这个 0，我是从**表**里读的，还是从**调用链**里读的？
- 写下这个 0 的代码在哪一行？如果我说不出来，那我凭什么叫它「机制在」？
- 如果这条链路从今天开始跑，谁会知道？有没有一条读数会在它跑起来时变化？
