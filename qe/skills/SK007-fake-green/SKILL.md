# 假绿锚点（判据自身恒真/边界过宽）
## 七种形态（全部长得像正常代码）

| 写法 | 为什么会假绿 |
|---|---|
| `assert('x', true)` | 常量真，占位忘删 |
| `assert('x', 'false')` | **非空字符串恒真**（最阴：看着像有判定） |
| `cond \|\| true` | 短路兜底 |
| `expect(n).toBeGreaterThanOrEqual(0)` | 计数天然 ≥0 |
| `path.startsWith('/admin')` 做权限 | `/admin` 命中 `/admin-evil` |
| `process.exitCode = 0` | 覆盖掉前面判红的退出码，CI 永远绿 |
| `if (false)` | 关掉判据的残留 |

## 为什么它是元判据

它找的不是业务 bug，是**守卫自己的病**。一个仓库最危险的状态不是红，
是绿得没有意义 —— 而人还会相信那个绿。

## 为什么放进通用引擎而不是各项目各写

这些形态与业务无关、每个项目都会犯（本项目两个仓库各犯过至少两次）。
它是「跨项目转移性 ✅ 直接搬」那一栏里最该先搬的东西。

## 修复形态

- 断言必须能说出「什么情况下它会红」；
- 计数类断言改成精确值或集合相等；
- 路径边界判定用 `path === prefix || path.startsWith(prefix + '/')`，或直接比较规范化后的段数组。
