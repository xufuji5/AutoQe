# 缺失型缺陷

## 真实形态

静态扫描的所有判据都在问「写出来的代码对不对」。而代价最高的一类缺陷是**根本没写**：
文档承诺了模型、字段、端点，代码里没有。它在类型系统里完全合法——没有任何东西引用它，
所以没有任何编译器、lint、测试会报错。

**这一族的检测器不在代码里，在文档库里。**

## 判据

`spec-abs`（INV-SPEC-01）：把文档里**显式声明**的模型 / 字段 / 端点，与实现对账。

| 声明 | 实现载体 | 缺口含义 |
|---|---|---|
| 模型表里的 `Tenant` | Prisma schema 的 `model` | 要么补模型，要么把规格标为废弃 |
| 字段表里的 `Tenant.code` | schema 里该模型的字段/列名 | 缺失型缺陷最典型的形态：没有引用，因此没有编译错误 |
| 端点表里的 `/api/tenants` | App Router 的 `route.*` 文件 | 调用方会拿到 404 |

## 为什么默认只出候选

文档会过期。拿 9 月的需求文档量 10 月的代码，会得到 65 个「缺失」——大部分是需求改了文档没改。
所以缺口默认是 **warn**：由人先判「规格是否仍有效」，再决定补代码还是删文档。
只有显式声明 `spec.docsOwner`（谁负责文档与实现同步）才允许 `enforce: true`。
**没人校准的尺子不能用来量人。**

## 自省

- 这条规格是谁写的、什么时候写的？它最近一次被确认有效是什么时候？
- 如果这条规格仍有效，为什么全仓没有一个引用？——「零引用」正是它躲过所有检查的原因。
- 我是在补代码，还是在删文档？两种都算修，但不能默认选补。
