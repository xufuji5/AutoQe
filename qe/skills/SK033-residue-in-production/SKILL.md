# 残留型缺陷

## 真实形态

AI 分模块开发时，为了「先跑起来」，最省力的路径是引用假数据。后来接口接上了，
**那条引用常常留着**——它不报错、类型也对、本地看起来一切正常，只是线上多了一份假数据。

第二形态是写死数组：`const products = [{...}, {...}, {...}]` 配一个 `.map()`。
接口接通后取数代码加上了，常量没删，于是线上同时存在两种数据。

两者都不产生错账，它们产生**对不上的数字**：页面显示 3 条，报表显示 24 条。

## 判据

| 判据 | 能证死的事实 | 档位 |
|---|---|---|
| `aq12`（INV-RES-01） | 生产源码显式 import 了 mock/seed/fixture 模块；动态 import 前 30 行没有 dev 门控 | machine → 可出 error |
| `aq13`（INV-RES-02） | 页面里有 ≥3 项对象数组被 `.map()` 渲染，且**本文件没有任何取数入口** | human → 只出 warn |

`aq13` 只能是候选：「占位数据」与「合法常量」（筛选项、导航表、模板骨架）在源码里长得一样。
机器只能把候选摆到人面前，由人按「这个页面是否已有真实数据来源」裁决。

## 自省

- 这个页面上的数据，能追到哪个接口？追不到时，它是写死的吗？
- 我删这个 import 之前，确认它没有被测试或脚本引用了吗？
- 如果这是合法常量，我能不能把内容型字段（name/price/img）换成纯配置字段（key/label）来消除歧义？
