# `qe/probe/` —— 运行期探针库（不是守卫）

这三份代码**不接入** `qe/cli.ts run`，也不会在任何守卫汇总里出现。

理由：守卫是「读代码就能判」的静态判据；这里的三个是**必须把程序跑起来**才能判的事。
把探针伪装成守卫，会得到一批永远绿的行 —— 那正是本项目最反对的东西（假绿）。

| 文件 | 回答什么问题 | 为什么静态判据答不了 |
|---|---|---|
| `fault-inject.ts` | 依赖故障时，降级分支真的执行了吗、语义对吗、有界吗、有声吗 | 「catch 里有没有动作」是形态；「那个动作执行了吗」是行为 |
| `concurrency-probe.ts` | 两个请求同时进来，是串行还是真的并发 | 静态扫描看不见调度顺序；单路测试永远全绿 |
| `head-consistency.ts` | 这次「绿」是对磁盘、索引还是 HEAD 绿的 | 三个投影都是运行时事实，不是源码文本 |

用法与纪律写在对应的知识条目里（`qe/skills/SK011-fault-injection`、`SK009-three-projections`），
那里同时写了「探针必须先对旧实现判红」这条前提 —— 没红过的探针等于没跑。

## 为什么放在引擎仓而不是各项目里

同一段 `installFaults` 被三个项目各写一遍，就是本项目一直在打的「双源」病。
接口只有一份，行为差异靠参数（`FaultRule`）表达，这样「所有项目都不许真实出站」才可能是一条机制。
