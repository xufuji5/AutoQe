# AI 写代码越来越快，质量谁来兜底？我开源了一个“不变量优先”的代码体检工具

> 备选标题：
> 1. 测试全绿，上线还是翻车？用 AutoQe 把“靠人记的规则”变成每次都会判红的检查
> 2. 给 AI 编码加一道质量闸：AutoQe 开源实践（附 5 分钟上手）

## 写在前面

这两年开发方式变了。需求丢给 Codex、Claude Code、WorkBuddy、Trae，几分钟就能生成一个能跑的模块。

但下面这些场景，做业务的人应该都不陌生：

- 字段建好了，代码里从来没人写，页面永远是空；
- 接口写完了，前端根本没有调用入口，联调时才发现“这个功能没做”；
- 单测全绿，上线后统计少了一半数据——查询漏了软删条件；
- 本地怎么跑都没事，CI 换台机器构建直接失败；
- 上线前清理代码，把带客户名的报告和扫描结果一起提交进了 Git。

它们有个共同点：**构建不报错、lint 不报错、测试也可能全绿，但都是真缺陷。**

测试只能覆盖你想到的路径；AI 生成的代码，缺陷往往是结构性的。靠人一条条 review、靠用例一个个补，很难追上生成速度。

所以我把自己一直用的质量工具整理开源了：**AutoQe**。

---

## AutoQe 是什么

一句话：**把“靠人记的质量要求”，变成每次运行都会判红的检查。**

它不跑你的测试，也不生成测试。它做的是静态扫描 + 不变量登记：

- 每条规则是一条“对一切实例都成立”的**不变量**，不是某条路径的用例；
- 每条不变量登记在 registry 里，写清楚状态（`enforced` / `partial` / `open`）、盲区和复审日期；
- 每个守卫（guard）必须先在**独立构造的坏样本**上变红，才算可信；
- 所有问题计数进入**棘轮基线（ratchet）**，只能降不能升，回归直接让 CI 变红；
- 看不到检查对象时，明确输出 `skipped`，绝不报“0 个问题”。

目前内置：**56 条不变量**（23 enforced / 30 partial / 3 open）、**40 个守卫**、**22 条纯函数规则**、**42 条来自真实事故的知识库**、**393 个坏样本自证**。

## 它具体能查什么

| 类别 | 典型问题 | 对应守卫 |
|---|---|---|
| 数据与结构 | 零写列、零读列、死枚举；软删表查询漏谓词 | `inv01`–`inv03`、`inv25` |
| 服务端边界 | 入口缺鉴权/校验/幂等；公开路由没写理由；变更接口没有限流 | `inv20`、`aq01`、`aq06`、`inv28` |
| 前后端接缝 | 客户端直接 import Prisma/Node；接口有服务端实现但界面没有真实发送点 | `inv21`、`inv23` |
| 并发与一致性 | check-then-act、跨租户 SQL 少了租户条件、IDOR、无幂等键写入、事务内做唯一冲突回退 | `aq04`、`aq05`、`aq08`–`aq10`、`aq14` |
| 假绿 | 永远不会失败的断言、状态机字面量副本、吞掉的错误、硬编码数据 | `aq02`、`aq03`、`aq07`、`aq13` |
| 承诺与可寻址 | 文档承诺了却没有执行点、空转闸、守卫没登记、断言对象在 CI 里不存在 | `inv06`、`inv07`、`inv13`、`inv24`、`spec-abs` |
| 交付 | HEAD 在干净检出里构建不了；工具路径依赖当前目录 | `inv27`、`aq11` |
| 泄漏 | 本机路径、凭据、项目代号进入文件、提交信息或 Git 索引 | `leak` |
| 小程序 | 定时器打到已销毁页面、组件隔离样式缺失、首渲染前 setData、tabBar 页面 navigateTo 等 | `mp01`–`mp08` |

每条规则都能用一条命令看细节：规则是什么、盲区在哪、坏样本长什么样、怎么复现。

## 为什么它适合 AI 编码

AI 写代码最大的问题不是“不会写”，而是**它不知道自己哪里没写对**。AutoQe 的做法是把“判定权”从模型手里拿走：

1. **AI 读 `AGENTS.md` 按协议干活**：先查不变量，再跑守卫，最后才写结论；没有命令读数或台账记录，不许说“完成”。
2. **只认命令读数**：`QE_RESULT`、`GUARD_SUMMARY`、`RATCHET` 是事实，模型的“看起来没问题”不算结论。
3. **跳过就是黄色**：没配置、没对象、没跑到的守卫报 `skipped`，不会被包装成“0 问题”。
4. **基线只降不升**：新问题进不了基线；局部运行时未覆盖的键报 `unverified`，也不会被当成“改善”。

这套约束对 Codex、Claude Code、WorkBuddy、Trae 都适用，不绑定具体模型。

## 5 分钟上手

### 方式一：下载解压，交给 AI 工具（推荐）

1. 把仓库下载成 zip，解压到**任意目录**。引擎不需要放进被扫描的项目。
2. 用 Codex / WorkBuddy / Trae / Claude Code 打开这个目录。
3. 在引擎目录执行一次 `npm install`（唯一运行时依赖是 `typescript`）。
   - 国内网络慢可以先切镜像：`npm config set registry https://registry.npmmirror.com`
   - Node 要求：**>= 22.18**（原生 TS 类型擦除，不需要构建）。
4. 直接对 AI 说一句话：

   > 用 AutoQe 扫描 `<项目路径>`：先读 `AGENTS.md`，然后 init、doctor、run、triage，最后把审计清单写到 `qe-audit/`。不要修改项目源码。

AI 会自动调用引擎里的命令：

```bash
node qe/cli.ts init   --root <project>   # 首次：写入配置、QE 文档和模板
node qe/cli.ts doctor --root <project>   # 预检：Node / 配置 / schema / 源码目录
node qe/cli.ts run    --root <project>   # 跑全部守卫
node qe/cli.ts triage --root <project>   # 分拣：自动修 / 需决策 / 备案
node qe/cli.ts report --root <project>   # 生成扫描报告
```

产出两份东西：

- `qe-report/qe-report.md`：机械扫描报告，带每类问题的计数与守卫读数；
- `qe-audit/<项目>-<日期>/`：AI 按 QE-03 作业单写的审计清单，包含事实基线、入口清单、扫描日志、带 `file:line` 的缺陷台账和上线判定。

> 首次运行经常是**黄色**，这是正常的：没配 schema、没声明软删表、仓库里没有小程序、没配限流形态，相关守卫都会明确说“本轮未检查”，而不是假装通过。按提示补配置即可，不要为了变绿去删检查项。

### 方式二：纯命令行

```bash
cd your-project
node <engine>/qe/cli.ts init
node <engine>/qe/cli.ts doctor
node <engine>/qe/cli.ts run --root .

node <engine>/qe/cli.ts triage --root .          # 分拣
node <engine>/qe/cli.ts ratchet-update --root .  # 确认后冻结基线
node <engine>/qe/cli.ts report --root .          # 输出报告
```

单条规则解释：

```bash
node <engine>/qe/cli.ts explain INV-CORE-01
```

## 同时扫多个项目，数据不会串

这是很多同类工具容易忽略、但团队用起来最痛的一点：**引擎可以复用，项目数据不能复用。**

AutoQe 把隔离做成了硬约束，而不是使用纪律：

- 每个项目有自己的配置、身份文件（`qe.project.json`）、基线和报告；
- 配置里声明的状态路径和扫描范围不能靠 `..` 逃出项目根，逃逸直接报错；
- 一个引擎同时扫多个项目时，`multi` 会**一个项目起一个子进程**，`cwd` 切到该项目，默认剥掉全部 `AUTOQE_*` / `QE_*` 环境变量；
- 每个子进程必须自报自己的 root，输出里出现别的项目路径就整批失败。

```bash
node qe/cli.ts multi --roots ../shop,../admin
```

如果只是临时体检别人的仓库、连一个配置文件都不想留下，用外部状态模式：

```bash
node qe/cli.ts run --root <other> --config <state>/qe.config.json
```

身份、基线和报告都落在配置文件旁边，被审计的仓库不会多出任何文件。

## 适合谁，不适合谁

**适合：**

- 用 AI 工具大量生成业务代码，review 压力大的团队；
- Next.js + Prisma + PostgreSQL / Zustand 技术栈的项目；
- 需要给 CI 加一道“质量闸”，但不方便大规模补测试的项目；
- 做微信小程序，被“样式没了 / 点了没反应 / 页面白屏”折磨过的同学；
- 想给 AI Agent 一套可执行质量协议，而不是一段“请注意代码质量”的提示词。

**不适合：**

- 想找“一键修完所有 bug”的工具——它只负责发现和取证，修复仍需人或 AI 逐条处理；
- 指望它替代 e2e、契约测试、压测——它明确不承担这些；
- 期待 100% 覆盖——每条规则都写了盲区，`open` 的不变量会直接列出来，不藏。

## 几个比较“较真”的设计

- **空集不算绿**：扫描 0 个对象不是通过，而是 `skipped` 或错误。很多“0 问题”其实只是没扫到。
- **基线只降不升**：棘轮计数只能变小；局部运行拒绝写基线（`RATCHET_REFUSE`），避免把没跑到的债务清零。
- **提交信息也扫**：泄漏检查不只看文件正文，还看提交信息和 Git 索引；`.gitignore` 只挡未跟踪文件，`git add -f` 之后照样判红。
- **数据和经验分开**：报告、审计区、一次性导出、黑名单属于数据（忽略，进索引即红）；规则、知识库、事故台账属于经验（跟踪、可复用）。

## 最后

项目地址（GitHub）：`https://github.com/xufuji5/AutoQe`

MIT 协议，Node >= 22.18，纯本地静态扫描，不依赖数据库、Docker 或任何云服务；引擎可以放在任意目录，用你常用的 AI 工具打开就能用。

如果你也在用 AI 写业务代码，欢迎拿一个真实项目跑一遍，把“它没查出来、但确实出过事”的缺陷类型提成 issue。对质量工具来说，**一条来自真实事故的规则，比十条拍脑袋的规则更有价值。**
