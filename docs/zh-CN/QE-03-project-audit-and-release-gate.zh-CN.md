# QE-03 · Project Audit and Release Gate

> Chinese edition of [QE-03-project-audit-and-release-gate.md](../../QE-03-project-audit-and-release-gate.md).

> 定位：**与具体业务无关**的作业单。拿到任何一个现有项目（不限 Next.js/Prisma），照此文档即可在半天内建立事实基线、快速整理出可复现的 bug 清单，并给出「能否上线」的可寻址结论。
> 配套：栈专用判据见 `QE-06~09`；缺陷分型见 `QE-04`；不变量三态见 `QE-05`；自动化守卫见 `AGENTS.md`。
> 产出：**Bug 台账 + 上线判定报告**（模板见 `qe/templates/project-audit/`）。所有结论必须带证据，禁止「看代码觉得没问题」。

## 0.1 在目标项目中的落地

1. 按 `QE-00-index.zh-CN.md` §7 复制「QE 复制包」到目标仓根目录（文档与 `qe/` 同级）。
2. 复制 `qe/templates/project-audit/` 到 `qe-audit/<项目名>-<日期>/`。
3. 按 S0→S4 填写五份文件：`00-fact-baseline`、`01-entry-inventory`、`02-scan-log`、`03-bug-ledger`、`04-上线判定`。
4. 五份文件不齐，不允许给出上线结论；判定结论必须引用 Gate 与 BUG ID。
5. 若体检引入了外部清单（通用审计包、第三方报告），填 `05-gap-absorption-plan.md`：每项写适用性、自有载体与验收读数；不适用/拒绝必须给理由。模板见 `qe/templates/project-audit/05-gap-absorption-plan.md`。

> 一个项目一个工作区；不要把上一个项目的台账复制进来当模板内容。
> 外部清单只提供问题，不提供结论：本项目已有且更严的守卫标「已有」，不要为了「吸收」而替换成外部形态。

## 0. 使用方式

| 阶段 | 时间盒 | 产出 | 退出条件 |
|---|---|---|---|
| S0 事实基线 | 30–60 分钟 | 可运行记录、命令清单、环境变量清单 | 能在干净环境构建并启动（或明确记录失败点） |
| S1 快速扫描 | 60–90 分钟 | 可疑点列表（未定级） | 每个入口/写路径都被扫过一遍 |
| S2 深挖 | 2–4 小时 | 已复现 bug + 证据等级 | P0/P1 全部有证据或明确排除理由 |
| S3 定级与修复 | 按量 | 修复 PR + 回归样本 | 每个修复有复验证据 |
| S4 上线判定 | 30 分钟 | 判定报告 | 12 道 Gate 逐条有结论 |

**三条原则**

1. **证据优先**：没有命令输出 / 复现步骤 / 测试断言的结论，一律标「未验证」，不计入上线判定。
2. **先广后深**：先扫全部入口与写路径，再挑高风险深挖；不要一头扎进第一个可疑点。
3. **按影响排序**：数据损坏、越权、资金错误优先于代码风格；能导致「静默错误」的优先于会报错的。

## 1. S0 · 建立事实基线

### 1.1 仓库与运行

| 检查 | 怎么做 | 记录 |
|---|---|---|
| 目录与模块边界 | 列出一级目录、入口目录、共享目录 | 模块清单（谁依赖谁） |
| 依赖与锁文件 | 检查 lock 文件是否存在、是否一致 | 包管理器与版本 |
| 构建 | 用仓库文档的命令，在干净环境构建 | 成功/失败 + 首个错误 |
| 类型/静态检查 | `typecheck` / `lint` | 错误数（不是「有没有配置」） |
| 测试 | 跑全量测试，记录通过/跳过/耗时 | 覆盖的核心路径 |
| 启动 | 按 README 启动，访问健康检查 | 启动耗时、健康端点 |
| 数据库 | 迁移能否在空库重放 | 迁移链完整性 |

> 构建失败、迁移不能重放、健康检查 404 —— 任意一项成立，直接记为 P0，后续深挖可暂缓。

### 1.2 环境与配置

- 列出代码中读取的全部环境变量，与 `.env.example` / 部署配置对拍；缺一即为「部署即炸」。
- 检查默认值方向：安全相关配置（鉴权 key、限流、开关）缺失时必须 **fail-closed**，不能默认放行。
- 检查密钥是否入库：`rg -n "(api[_-]?key|secret|token|password)\s*[:=]\s*['\"][^'\"]{8,}"`，命中即 P0。
- 检查 `.env*` 是否被版本控制；检查前端构建是否把服务端变量打进 bundle（`NEXT_PUBLIC_` / `VITE_` 前缀滥用）。

### 1.3 入口清单（后续所有检查的骨架）

把「外部能进来的地方」全部列出，一张表：

| 类型 | 例子 | 数量 |
|---|---|---|
| HTTP 路由 | route handler、controller、router | |
| Server Action | `'use server'` 导出 | |
| 队列消费者 | worker、consumer、cron | |
| Webhook | 支付/第三方回调 | |
| CLI / 脚本 | 运维脚本、迁移脚本 | |
| Agent/MCP 通道 | 工具调用入口 | |

> 入口清单不全，后面的鉴权/校验检查全部无效。**先列全，再判。**

## 2. S1 · 快速扫描（高收益模式）

> 命令以 ripgrep 为例；其他语言按同义模式替换。命中只是「可疑」，必须进入 S2 复核。

| # | 扫描项 | 命令 / 方法 | 看到什么算可疑 | 默认等级 |
|---|---|---|---|---|
| 1 | 入口鉴权缺口 | 对每个入口看函数体是否调用鉴权 | 只判断「已登录」、无对象级校验、公共入口无登记 | P0/P1 |
| 2 | 输入未校验 | `rg -n "request\.json\(\)|req\.body|ctx\.request"` 后看邻近是否有 schema/validate | body 直接进业务/ORM | P0 |
| 3 | 危险执行 | `rg -n "eval\(|new Function|child_process|execSync|\$queryRawUnsafe|\$executeRawUnsafe"` | 拼接用户输入 | P0 |
| 4 | XSS sink | `rg -n "dangerouslySetInnerHTML|v-html|innerHTML\s*="` | 未消毒的富文本/用户输入 | P0/P1 |
| 5 | 客户端越界 | `rg -l "use client"` 后查 import：`@prisma/client|server-only|next/headers|node:|fs|path|crypto` | 客户端直连服务端实现 | P0 |
| 6 | 先查后插 | `rg -n "findUnique|findFirst|exists\("` 附近有 `create` | 无唯一约束兜底 | P1 |
| 7 | 裸更新 | `rg -n "\.update\(\{\s*where:\s*\{\s*id"` / `save()` | 无前置状态/版本条件 | P0/P1 |
| 8 | 敏感落盘 | `rg -n "persist\(|localStorage\.setItem|sessionStorage"` | token/password/身份证进持久化 | P0 |
| 9 | 吞错 | `rg -n "catch\s*(\([^)]*\))?\s*\{\s*\}"` / 只 `console.log` 不抛 | 失败被当成功 | P1 |
| 10 | 公共入口 | 无鉴权入口逐个问「为什么可以公开」 | 无理由、返回业务数据 | P0 |
| 11 | 状态机裸迁移 | `rg -n "status\s*[:=]"` 附近的 update | 无前置状态谓词、不查影响行数 | P0 |
| 12 | 迁移漂移 | 空库执行全量迁移；对比 schema 与 DB | 失败 / 手工补列 / 缺索引 | P0 |
| 13 | 依赖漏洞 | `npm audit --omit=dev` / `pip-audit` / `govulncheck` | 高危且可利用 | P1 |
| 14 | 可观测缺口 | 查日志/错误上报/健康检查/请求 ID | 全无或只有 `console.log` | P1 |
| 15 | 资源上限 | 查 body 限制、分页上限、文件大小、限流 | 缺上限或直接透传 `take/limit` | P1 |

**扫描记录格式**：`文件:行 → 可疑点 → 为什么可疑 → 待验证方式`。不要在这一步写修复方案。

## 3. S2 · 深挖七条主线

每条主线按「检查项 → 判据 → 证据 → 默认等级」执行。适用项打勾，不适用写「N/A + 原因」。

| ID | 检查项 | 判据 | 证据 | 等级 |

## 4. S3 · 复现、定级与修复

### 4.1 证据等级

| 等级 | 含义 | 是否可用于上线判定 |
|---|---|---|
| E0 | 静态可疑（代码/配置） | 只能作为「待验证」，不能单独判 P0 |
| E1 | 单测/构造用例复现 | 可以 |
| E2 | 集成/接口级复现 | 可以 |
| E3 | 真实环境/生产影子复现 | 可以，优先级最高 |

> E0 不是缺陷结论，是线索。上线判定只认 E1–E3。

### 4.2 等级定义

| 等级 | 判定标准 | 例子 | 上线处理 |
|---|---|---|---|
| P0 | 数据损坏/资金错误/越权/无法启动/无法回滚 | 重复扣款、匿名读全表、迁移失败 | **必须清零** |
| P1 | 核心路径不可用或可被条件利用 | 登录偶发失败、越权需特定参数、队列积压 | 修复或有书面豁免 + 监控 + 时限 |
| P2 | 边缘场景、性能退化、体验问题 | 大分页慢、空态缺失 | 可排期，记录 |
| P3 | 代码质量/可维护性 | 重复代码、命名 | 不阻断 |

### 4.3 Bug 台账字段（直接可贴进表格）

| 字段 | 要求 |
|---|---|
| ID | `BUG-<模块>-<序号>` |
| 标题 | 一句话说清「什么条件下发生什么」 |
| 模块/入口 | 文件:行 + 入口名 |
| 现象 | 用户/系统看到什么 |
| 根因 | 违反哪条约束（引用 INV-ID 或检查项 ID） |
| 证据 | 等级 E0–E3 + 复现命令/用例路径 |
| 等级 | P0–P3 |
| 影响面 | 用户量/数据量/资金/合规 |
| 修复 | PR/commit |
| 复验 | 回归用例 + 读数 |
| 状态 | 待修/修复中/已复验/豁免（含理由与到期日） |

### 4.4 修复纪律

1. **先加判据，再改代码**：能写成守卫/测试的，先让它对旧代码见红，再修到绿。
2. **一次只改一类**：不要在修并发 bug 的 PR 里顺手重构。
3. **修复必须有反例**：坏样本由非实现者构造；修完后坏样本必须仍然存在并变红→绿。
4. **基线只降不升**：存量缺陷修一个少一个，新违规不得入基线（QE-02）。
5. **不可逆动作**：删列/改历史数据/换密钥必须先备份 + 演练回滚。

## 5. S4 · 上线判定（12 道硬 Gate）

> 任一道为「否」且无书面豁免，结论只能是「不可上线」或「有条件上线」。

| Gate | 判据 | 证据 | 结论 |
|---|---|---|---|
| G1 可构建 | 干净环境构建成功 | CI 日志 | |
| G2 可迁移 | 空库全量迁移成功 | 迁移日志 | |
| G3 P0 清零 | 台账 P0 = 0 | 台账 | |
| G4 P1 有处置 | 修复或有豁免（理由+监控+到期日+责任人） | 台账 | |
| G5 权限矩阵 | 入口表逐条有身份判定，越权用例通过 | 用例 | |
| G6 核心路径 e2e | 登录→核心业务→支付/提交→查询全通 | e2e 报告 | |
| G7 数据约束 | 唯一键/事务/幂等四项适用项有证据 | 代码+测试 | |
| G8 安全基线 | 密钥扫描干净、无已知高危、输出不泄漏 | 扫描输出 | |
| G9 资源上限 | 体积/分页/限流适用项有配置或说明 | 配置 | |
| G10 可观测 | 错误率/延迟/积压面板 + 告警接收人 | 截图 | |
| G11 可回滚 | 应用回滚 + 数据补偿演练通过 | 演练记录 | |
| G12 生产冒烟 | 生产同构环境冒烟通过 | 冒烟输出 | |

**判定输出**

- **可上线**：G1–G12 全部「是」。
- **有条件上线**：仅 G4/G9/G10 可为「有条件」，且必须写：条件、监控指标、决策人、失效时间。
- **不可上线**：G1/G2/G3/G5/G6/G7/G8/G11 任一为否。

> 「先上再看」不是判定，是赌博。若必须冒险，写清爆炸半径、回滚触发条件与值守人。

## 6. 常见假绿（必须逐条排除）

| 假绿 | 为什么骗人 | 排除方法 |
|---|---|---|
| 守卫扫到 0 个对象就报绿 | 空集恒真 | 检查 `scanned=` 计数；0 对象应 skipped/报错 |
| 测试只覆盖 happy path | 错误分支从未执行 | 构造失败/越权/重放用例 |
| 本地能跑 | 依赖本机缓存与手工数据 | 干净环境 + 空库 |
| 测试没有断言 | 跑通不等于对 | 检查断言与失败注入 |
| 日志无异常 | 吞错/未记录 | 注入失败，看是否可观测 |
| Mock 全通过 | 真实契约漂移 | 契约测试/联调 |
| 鉴权在测试环境关闭 | 生产才暴露 | 测试环境同构 |
| 数据库有种子数据 | 掩盖迁移/约束问题 | 空库重放 |
| 只看了入口 | 队列/定时/webhook 未覆盖 | 入口清单对账 |

## 9. 与自动化守卫的配合

| 体检项 | 自动化（本工具箱） | 仍需人工 |
|---|---|---|
| C2/C3 鉴权 | `inv20` 判「有没有」 | 对象级授权是否完整 |
| C4 校验 | `inv20` 判「有没有 schema 校验」 | 范围/白名单是否正确 |
| C5 客户端越界 | `inv21` | 别名/barrel/动态导入 |
| C6 跨模块 | `inv21`（相对路径） | 别名与包边界 |
| B3 零写列/死枚举 | `inv01` / `inv03` | 语义是否正确 |
| D3 幂等 | `inv20` 告警 | 去重是否落库、同事务 |
| F1/F2 持久化 | `inv22` | 迁移函数正确性 |
| 基线回归 | `ratchet` | 判定是否合理 |

> 自动化只负责「形状」，不负责「语义」。`green` 不等于「安全」，只等于「这一条判据没被违反」。

## 10. 收尾

- 台账与判定报告必须能被下一个人独立复现：命令、版本、环境、数据状态写全。
- 每个豁免都有到期日；到期未处理自动回到 P1。
- 上线后 24–72 小时按 G10 面板复核：错误率、时延、队列积压、资金/资产余额差异；异常即触发回滚条件。
